# Tauri + Rust 批量重命名工具 —— 项目规格说明书（AI 编码用）

## 一、项目目标
使用 Tauri v2 开发跨平台桌面应用，实现批量重命名文件夹及其子目录下的文件。

## 二、技术栈约束
| 层级     | 技术选型                                                                                                                        |
| -------- | ------------------------------------------------------------------------------------------------------------------------------- |
| 后端     | Rust（最新稳定版）+ Tauri v2                                                                                                    |
| 前端     | TypeScript + 推荐 Vanilla TS + Vite（最轻量）                                                                                   |
| 关键依赖 | `serde`（序列化）、`anyhow`/`thiserror`（错误处理）、`regex`（正则替换）、`walkdir`（递归遍历）、`tokio`（仅 `spawn_blocking`） |

## 三、核心架构铁律（必须遵守）

### 3.1 异步与非阻塞
- 所有 Tauri 后端命令必须标记为 `async`
- 文件 I/O（`fs::rename`、`fs::read_dir` 等）**不得**直接在 async 命令顶层执行，必须放入 `tokio::task::spawn_blocking`
- 前端在执行耗时操作时必须显示 Loading 状态，并禁用操作按钮

### 3.2 预览先行（不可违反）
- 提供两个独立命令：
  - `get_preview`：仅计算新旧文件名映射，**绝对不修改磁盘**
  - `execute_rename`：批量执行重命名
- 前端流程：选路径/设规则 → 点击预览 → 展示表格 → 用户勾选确认 → 点击执行

### 3.3 细粒度错误处理
- 单个文件失败不得导致整体任务中止
- 返回每个文件的操作结果（成功/失败+原因）
- **全项目禁止 `unwrap()`**，所有 `Result` 通过 `?` 或自定义错误向上传播

## 四、功能需求清单

### 4.1 路径与递归
- [ ] 输入框 + “浏览”按钮（调用系统文件夹对话框）
- [ ] “包含子目录”复选框：启用后递归遍历所有子文件夹
- [ ] 保持原目录结构，文件原地重命名（不移动位置）

### 4.2 文件遍历与分组排序
- [ ] 使用 `walkdir` 进行递归遍历
- [ ] 按父目录路径对文件分组
- [ ] 每个分组内独立排序（按文件名 / 按修改时间，用户可选）
- [ ] 每个分组的编号计数器**独立从 1 开始**

### 4.3 重命名模式（三种，通过 Tab/单选框切换）

#### 模式 A：查找替换
- 输入“查找文本”和“替换文本”
- “使用正则”复选框（启用时使用 `regex` crate）

#### 模式 B：序号命名
- 输入“前缀”（默认 `file`）和“起始数字”（默认 `1`）
- **动态补零位数**：由当前分组文件总数决定
  - 若该分组有 120 个文件 → 3 位（001~120）
  - 若该分组有 5 个文件 → 1 位（1~5）
  - **各组独立计算，不强制全局统一**

#### 模式 C：统一后缀
- 输入目标后缀（不带点号，如 `jpg`）
- “强制转换所有扩展名”复选框（默认勾选）
- “将后缀转为小写”复选框（默认勾选）
- 此模式**不修改主文件名**，仅变更扩展名部分
- 若原后缀与目标后缀（忽略大小写）一致 → 状态为“无变化”

### 4.4 过滤与白名单
- [ ] 扩展名白名单输入框（逗号分隔，如 `png,jpg,mp4`，留空不过滤）
- [ ] 递归遍历时过滤规则依然生效

### 4.5 预览表格数据
- 返回字段：`id`、`relative_path`、`old_name`、`new_name`、`status`
- 状态枚举：`"ok"`（待执行）、`"conflict"`（冲突）、`"unchanged"`（无变化）

### 4.6 执行与反馈
- [ ] 执行过程中通过 Tauri `emit` 事件实时推送进度（当前数/总数）
- [ ] 执行完成后自动刷新预览
- [ ] 操作日志记录每次重命名的成功/失败结果

## 六、数据模型（Rust 结构体定义）

```rust
// 预览返回项
struct PreviewItem {
    id: usize,
    relative_path: String,   // 如 "assets/icons/"
    old_name: String,        // 完整原文件名
    new_name: String,        // 完整新文件名
    status: Status,          // "ok" | "conflict" | "unchanged"
}

// 执行请求
struct ExecuteRequest {
    ids: Vec<usize>,         // 仅包含用户勾选且状态为 ok 的项
}

// 执行结果
struct ExecuteResult {
    id: usize,
    success: bool,
    message: String,         // 成功信息或错误原因
}
```

## 七、前后端通信协议
### 7.1 Tauri 命令清单

|       命令名       |                            输入参数                            |       返回类型       |           说明           |
| :----------------: | :------------------------------------------------------------: | :------------------: | :----------------------: |
|   `get_preview`    | `{ root_path, recursive, mode, params, filter_exts, sort_by }` |  `Vec<PreviewItem>`  |    纯计算，不修改磁盘    |
|  `execute_rename`  |                      `{ root_path, ids }`                      | `Vec<ExecuteResult>` |      批量执行重命名      |
| `cancel_operation` |                              `{}`                              |          ()          | 取消进行中的操作（可选） |
### 7.2 进度事件（前端监听）

+ 事件名：`rename-progress`

+ 数据：`{ current: usize, total: usize }`

## 八、错误处理规范

+ 所有错误必须通过自定义错误类型返回给前端

+ 错误信息需包含足够的上下文（如“权限不足: `/path/to/file`”）

+ 前端根据返回结果显示对应颜色的状态提示

## 九、代码输出要求

+ `Cargo.toml` 完整依赖（含     `tauri` 特性、`walkdir`、`tokio`、`serde`、`anyhow`、`regex`）

+ Rust 后端（`src-tauri/src/lib.rs`）：全部命令实现，展示 `spawn_blocking` 用法

+ 前端核心逻辑（App.tsx）：命令调用、状态管理、表格渲染

+ 自定义错误类型实现：`Into<tauri::Result> trait`

## 十、额外约束

+ 所有异步任务需支持取消（通过 `CancellationToken`）

+ 预览阶段生成的映射关系在执行阶段需重新计算，不信任前端传入的文件名（防止篡改）

+ 冲突检测在预览和执行两个阶段都要进行（执行时文件系统状态可能变化）
